# TL-DW - Too Long; Didn't Watch

TL-DW turns a local meeting recording into:

- a normalized, timestamped speech transcript;
- a small set of meaningful screen frames with optional local OCR;
- ordered multimodal sections in `analysis.json`;
- a readable transcript document;
- optional local context documents with embedded raster diagrams;
- an evidence-based meeting report **or operational planning document**, generated by any image-capable model configured in Pi.

Speech, frame extraction, OCR and document conversion run locally. When you explicitly request Pi analysis, bounded transcript sections, selected images **and any prepared context documents/diagrams** are sent to the chosen model. Document conversion never uses hosted OCR or a network fallback.

## How it works

### 1. Local preparation

The Python CLI:

1. probes the recording with FFprobe, checks required tools and estimates temporary disk space before loading models;
2. conservatively selects audio (deduplicating identical tracks and excluding only full-duration near-silence), then extracts mono 16 kHz audio;
3. applies the merged speech-focused normalization pipeline by default;
4. transcribes with `faster-whisper` (default: `large-v3`, beam size 5, VAD enabled);
5. scans frames cheaply at a low rate, scores visual changes, keeps one anchor plus meaningful changes per time section, and removes the rest;
6. optionally enriches retained frames with RapidOCR in an isolated worker process;
7. writes a portable `analysis.json` that aligns speech and images chronologically.

The default audio filter is:

```text
highpass=f=80,dynaudnorm=f=250:g=15:p=0.95,loudnorm=I=-16:TP=-1.5:LRA=11
```

Audio/video speed-up is deliberately not applied. It can alter ASR accuracy and would require timestamp rescaling; local ASR plus visual deduplication saves model cost without that quality risk.

### 2. Pi analysis

The local Pi package exposes:

- the `/skill:tl-dw <video>` skill for the complete prepare-and-analyze workflow from any directory;
- the model-callable `tl_dw_video` tool used by that skill;
- `tl_dw_analyze` and `/tl-dw-analyze` for an already prepared bundle, including planning and optional context documents.

The analyzer:

- uses an authenticated image-capable model;
- analyzes sections sequentially, carrying a compact evidence state forward;
- sends at most the selected frames for the current section;
- checkpoints each section so interrupted work can resume without repaying completed calls;
- analyzes explicit context documents/diagrams separately from meeting evidence;
- shares meeting checkpoints between summary and planning, without redoing ASR/OCR;
- previews new model calls and images, refusing before any calls if a requested ceiling would be exceeded;
- performs a final text-only synthesis;
- writes the report as `<summary>.md`, named from its subject, plus usage metadata.

## Requirements

- Python 3.13 (selected by the versioned `.python-version`)
- [uv](https://docs.astral.sh/uv/) 0.6.10+; CI pins 0.13.5
- `ffmpeg` and `ffprobe` on `PATH`
- Pi 1.4.0+ for analysis; an authenticated image-capable model chosen by each user
- enough disk/RAM for the chosen Whisper model

Development additionally requires Node.js 22.19+ and Bun 1.4.4+ (CI uses Node 24 and Bun 1.4.4). Python tests, extension tests and package-install smoke tests need **no model account, API keys, cached Whisper models or personal Pi installation/configuration**. Linux and macOS are covered by CI; Windows is not currently validated.

On macOS:

```bash
brew install ffmpeg uv
```

## Install

Install the shareable Pi package directly from Git:

```bash
pi install git:github.com/k33wee/TL-DW
```

Or clone the repository and prepare its locked Python environment:

```bash
git clone https://github.com/k33wee/TL-DW.git
cd TL-DW
uv sync --locked
```

Install this checkout as a Pi package so the skill, tool, and command are available from every working directory:

```bash
pi install "$(pwd)"
```

Pi loads a local checkout directly, so subsequent edits do not require reinstalling. Run `/reload` in an existing Pi session after changing the package. Authenticate to your own model provider with Pi's normal `/login`; no maintainer-specific model aliases, credentials or configuration files are shipped.

The extension resolves its Python project relative to its own package file, not a fixed checkout path or the user's home directory. It invokes `uv run --locked --project ...`, so preparation also works when Pi starts in an unrelated directory. The skill, extension, Python sources, Python version and `uv.lock` are included in the distributable package.

Optional NVIDIA runtime libraries:

```bash
uv sync --extra cuda
export LD_LIBRARY_PATH="$(uv run python -c 'import os; import nvidia.cublas.lib; import nvidia.cudnn.lib; print(os.path.dirname(nvidia.cublas.lib.__file__) + ":" + os.path.dirname(nvidia.cudnn.lib.__file__))')"
```

Optional wtpsplit SaT paragraph segmentation (the lightweight built-in segmenter is the default):

```bash
uv sync --extra sat
```

CUDA still requires a compatible NVIDIA driver. Current faster-whisper/CTranslate2 releases expect CUDA 12 cuBLAS and cuDNN 9. Use `--hardware-profile cuda-pascal` for GTX 10-series cards and `cuda-modern` for newer GPUs.

## Prepare a meeting

High-quality Italian example:

```bash
uv run tl-dw \
  --video "ScreenRec-2026-09-30-16.04.32.mp4" \
  --whisper-language it \
  --hardware-profile macbook \
  --segment-unchaptered \
  --timestamp-paragraphs \
  --add-table-of-contents
```

The equivalent portable entrypoint is:

```bash
uv run python main.py --video "recording.mp4"
```

Process every supported video in `videos/`:

```bash
uv run tl-dw
```

Force offline model loading after Whisper is cached:

```bash
uv run tl-dw --video "recording.mp4" --local-files-only
```

### Important preparation options

Speech:

- `--whisper-model`: model name/path; default `large-v3`.
- `--whisper-language`: language code such as `it` or `en`; empty enables detection.
- `--hardware-profile`: `auto`, `cpu`, `macbook`, `cuda-pascal`, or `cuda-modern`.
- `--whisper-device`, `--whisper-compute-type`: low-level overrides.
- `--beam-size`: default `5`.
- `--no-vad`: disable voice-activity filtering.
- `--normalize-audio` / `--no-normalize-audio`: enabled by default.
- `--normalization-filter`: custom FFmpeg filter.
- `--initial-prompt`: vocabulary/style hint for Whisper. Embedded titles and chapter names are used when this is omitted. A title that only repeats an opaque recording filename is ignored.
- `--local-files-only`: prohibit model downloads.

Visual analysis:

- `--frame-sample-sec`: visual scan interval; default `5` seconds.
- `--section-seconds`: analysis section duration; default `120` seconds.
- `--max-frames-per-section`: default `4`.
- `--frame-min-change`: minimum novelty score; default `0.015`.
- `--frame-max-dimension`: retained image width limit; default `1600`.
- `--no-ocr`: keep images but skip local OCR.
- `--no-frames`: create a transcript-only bundle.

Document formatting:

- `--segment-unchaptered`
- `--timestamp-paragraphs`
- `--add-table-of-contents`
- `--sat-model simple` (default) or a SaT model installed through the `sat` extra

Run `uv run tl-dw --help` for the full list.

## Preflight, audio tracks and local resume

```bash
# Probe and estimate local space only: no model loading or transcription.
uv run tl-dw --video recording.mp4 --preflight-only

# A directory passed as --video must contain exactly one supported video.
uv run tl-dw --video ./meeting-folder

# Distinct non-silent tracks require an explicit choice; these are absolute
# FFprobe stream indices, not audio-relative offsets.
uv run tl-dw --video recording.mkv --audio-stream 1
uv run tl-dw --video recording.mkv --audio-mix 1 2
```

For multiple tracks, full-track volume diagnostics are the default. Packet hashes plus codec/layout/timing identify exact duplicates. Near-silence is a recorded peak threshold (`-80 dB` over the full inspected track), not speech/language detection. If more than one distinct non-silent track remains, preparation stops **before ASR** with `audio-selection.json` and asks for a stream or explicit mix. It never assumes that the first track contains every speaker. `--audio-diagnostics sample` samples beginning/middle/end volume, but a quiet sample is **not** grounds to discard a whole track. No compression, speed-up, original-media overwrite or automatic ambiguous mix occurs.

Preparation now checkpoints audio selection, extracted audio, completed transcription, frames/OCR and the bundle. Source/settings and output checksums are verified before reuse; interrupted/incomplete stages are rebuilt. Models are loaded lazily only when their stage needs them. `--force-preparation` explicitly rebuilds local stages; it is separate from Pi's `--force`, which repays model analysis. An interruption *during* one ASR/frame stage restarts that stage, not individual Whisper segments or frames. Legacy output without preparation provenance is not adopted or silently retranscribed: preparation refuses it unless `--force-preparation` is explicit. Analyze its existing `analysis.json` directly instead.

Temporary space is a conservative heuristic for PCM/chunks/frame scans on the chosen output volume, excluding model downloads; actual usage depends on the video. Audio chunks and scan scratch stay in the artifact directory. Filesystem/permission and model availability errors remain explicit.

## Context documents and operational planning

Attach only files/directories the user explicitly supplied for this analysis:

```bash
uv run tl-dw --video ./meeting-folder --attachment ./meeting-folder

# Add/revise context on an existing bundle WITHOUT loading ASR/OCR models.
uv run tl-dw --bundle output/recording --attachment specification.docx --attachment context.pdf
```

Directory attachments scan supported files at the top level only. Markdown/text, Office/OpenDocument/RTF/EPUB/CSV/PDF and explicit raster images are supported through local conversion. Embedded Office raster figures are normalized, deduplicated and kept with source provenance. **PDF is text-only here**: important embedded/vector diagrams must be supplied as explicit raster attachments. Image-only/scanned PDF conversion fails explicitly rather than sending the file to hosted OCR.

Limits: 20 files, 20 MiB per source, 200,000 total text characters, 40 unique figures, 6 MiB per normalized figure; bounded archive decompression and image pixels. Oversized/unsafe input fails rather than silently dropping context. Documents and diagrams are treated as untrusted evidence, never executable instructions.

In Pi:

```text
/tl-dw-analyze output/recording --report-mode planning --attachment "Specification.docx" --planning-request "Plan my next weeks; keep unassigned work conditional" --max-model-calls 10 --max-images 40
```

Or ask naturally for a complete planning document from an existing bundle. The `tl_dw_analyze` tool supports `input`, `attachments`, `report_mode`, `planning_request`, `max_model_calls`, `max_images`, `model` and `force`. `tl_dw_video` exposes the same workflow options plus audio selection and `force_preparation`.

Prepared context is included on later analyses of that bundle. Document provenance binds it to the prepared `analysis.json`; reattach explicitly after changing that preparation. Context parts honor the model image limit without silently losing diagrams. Planning distinguishes meeting agreements, attachment-only requirements, proposed estimates, parked/unassigned work and unresolved decisions. It must not claim live Jira/Git/API/DB state or turn proposals into commitments. Generated factual accuracy still needs human review.

`pi-analysis/analysis-preview.json` records the number of **new** calls/images for the invocation. Limits refuse the whole invocation before any model calls; they are not truncation settings or currency guarantees. A completed cached report uses zero calls. Summary and planning have separate run records and report filenames, sharing meeting checkpoints; changing documents only redoes document analysis and synthesis. Do not analyze the same artifact directory concurrently from different Pi processes; local preparation has an OS lock, and analysis also rejects concurrent work in one extension runtime.

## Analyze with Pi

After the personal package install, start Pi in any directory and point the skill at a video:

```text
/skill:tl-dw path/to/recording.mov
```

The skill calls `tl_dw_video`, which writes artifacts under `./tl-dw-output/<video-slug>/` by default and returns the completed Markdown report. Relative video and output paths resolve from Pi's working directory. The active model is used when it accepts images; pass a different model only when needed.

You can also ask naturally, for example:

```text
Use TL-DW to summarize ./recordings/sprint-review.mp4 in Italian.
```

For an already prepared bundle, use the lower-level command:

```text
/tl-dw-analyze output/recording
```

You can pass either `analysis.json` or its artifact directory. Pi opens a picker containing configured image-capable models. Choose one explicitly with:

```text
/tl-dw-analyze output/recording --model provider/model
```

Re-running the same bundle/model reuses a completed report or section checkpoints. To intentionally pay for a fresh analysis:

```text
/tl-dw-analyze output/recording --model provider/model --force
```

For one-off extension development without installing the package:

```bash
pi --extension .pi/extensions/tl-dw.ts
```

## Output

The Python CLI stores artifacts in `output/<video-slug>/` by default. The global Pi skill instead uses `./tl-dw-output/<video-slug>/` in the directory where Pi was started:

| File | Purpose |
|---|---|
| `metadata.json` | FFprobe metadata |
| `preflight.json` | Media facts, temporary-space estimate and compression policy |
| `audio-selection.json` | Stream choice, duplicate/silence diagnostics and their scope |
| `preparation.json`, `asr.json` | Content-checked stage checkpoints and completed structured ASR |
| `provenance.json` | Source checksum, audio choice, output checksums and stages executed/reused in this invocation |
| `documents.json`, `documents/` | Explicit context, source checksums, local Markdown and normalized figures |
| `audio.wav` | mono 16 kHz ASR input, normalized by default |
| `transcript.txt` | complete readable timestamped ASR |
| `transcript.jsonl` | structured ASR segments |
| `transcript_info.json` | model/runtime/preprocessing settings |
| `frames/` | selected images only |
| `frames.json` | frame timestamps, novelty scores, reasons, and OCR |
| `ocr.jsonl` | raw and filtered OCR observations |
| `visual_notes.json` | deduplicated OCR notes for the transcript document |
| `analysis.json` | ordered Pi-ready speech/image sections |
| `chapters.json` | rendered paragraph/chapter structure |
| `<summary>.md` | readable full transcript plus OCR notes and the selected screenshots they describe; the filename and heading are a short summary of the transcript |
| `pi-analysis/section-*.json` | resumable Pi section checkpoints |
| `pi-analysis/run.json`, `planning-run.json` | Separate synthesis metadata and successful aggregate usage |
| `pi-analysis/document-*.json` | Resumable context-document evidence notes |
| `pi-analysis/analysis-preview.json` | New model-call/image counts before spending |
| `<summary>.md` | final multimodal meeting report; the filename is a short subject summary, and useful screenshots are embedded with relative links |

## Quality and cost choices

- `large-v3` is the quality-first ASR default. Use `small` or `medium` when local runtime matters more.
- A two-minute section with at most four selected frames is the default compromise between visual recall and model cost.
- Every section retains an anchor even when the screen is static; extra images must pass a visual-change threshold.
- OCR supplements images but does not replace them. The Pi model receives both because desktop OCR can be noisy.
- Final synthesis is text-only; images are paid for only during their relevant section.
- `pi-analysis/run.json` totals successful calls. Provider dashboards remain authoritative for failed calls whose usage may not be returned.
- Section checkpoints are model-, extension-, and bundle-specific, preventing stale results from being silently reused.

## Current limitations

- The transcript does not perform speaker diarization. The Pi prompt explicitly avoids inventing speaker identities.
- OCR quality depends on font size and resolution; the vision model should treat OCR as fallible.
- Screen changes shorter than the frame scan interval can be missed. Lower `--frame-sample-sec` for rapidly changing demos.
- Meeting analysis sends selected images and transcript text to the chosen model provider; review privacy requirements first.

## Development and validation

From a fresh checkout, with Node, Bun, uv and FFmpeg installed:

```bash
npm ci --ignore-scripts --no-audit --no-fund
uv sync --locked --extra dev

npm run check                         # strict TypeScript, extension tests, Pi install/discovery smoke
uv run --locked ruff check tl_dw tests scripts
uv run --locked pytest -q             # synthetic media/documents, no real ASR/model downloads
```

`package-lock.json` pins JavaScript development dependencies, including the Pi SDK used by tests. There is no `NODE_PATH`, global module lookup or personal settings prerequisite. At runtime Pi supplies its own API peers; the test SDK is a **devDependency**, not a second bundled runtime host. `uv.lock` pins Python dependencies, and Ruff configuration is in `pyproject.toml` rather than a maintainer's home directory.

The install smoke test invokes the real Pi CLI and resource loader with an empty temporary home, an unrelated working directory and no inherited credentials, settings or global extensions. It verifies discovery of both tools, the command and the skill without making model calls. Other tests use actual FFmpeg and local document conversion on synthetic inputs, with ASR/model responses mocked.

Check the distributables too:

```bash
uv build --out-dir dist
npm pack --ignore-scripts --pack-destination dist
uv run --locked python scripts/check_distributions.py dist
```

The audit checks wheel/sdist/npm archives for required resources (including `.python-version`) and rejects private/local artifacts or archive links. `.github/workflows/ci.yml` runs these checks on Linux and macOS without model credentials or publishing/deploying anything.

### Shared code versus personal state

- **Versioned:** `.pi/extensions/`, `.pi/skills/`, Python/TypeScript sources, tests, manifests, lockfiles and CI.
- **Local and ignored:** `.pi/memory/`, `.pi/local-memory/`, personal `.pi/settings*.json`, `.env*`, recordings, generated reports, caches, `node_modules/` and `.venv/`.
- The `.pi` name does not make the extension/skill personal configuration: their paths are declared explicitly in `package.json` and shipped as package resources. No memory adapter or private workspace configuration is required.

Packaging is allowlisted. Never force-add recordings, customer documents, generated analyses or credentials to this repository.
